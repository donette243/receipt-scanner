# Receipt Scanner / Categorizer

Веб-приложение для распознавания кассовых чеков, автоматического извлечения информации о покупках, категоризации товаров и анализа расходов.

Пользователь загружает фотографию чека, после чего приложение обрабатывает изображение с помощью OpenCV, распознаёт текст через Tesseract OCR, извлекает данные о покупке, определяет категории товаров и сохраняет результат в MySQL.

## Основные возможности

- загрузка изображений кассовых чеков;
- предварительная обработка изображений с помощью OpenCV;
- распознавание текста через Tesseract OCR;
- поддержка русского, английского и французского языков;
- извлечение магазина, даты и итоговой суммы;
- извлечение названий товаров, количества и цены;
- автоматическая категоризация товаров;
- опциональная категоризация через LLM;
- сохранение результатов в MySQL;
- просмотр истории чеков;
- удаление сохранённых чеков;
- статистика расходов по категориям;
- REST API на FastAPI;
- интерактивная документация Swagger UI;
- миграции базы данных через Alembic;
- автоматические тесты с pytest;
- адаптивный веб-интерфейс на русском языке.

## Стек технологий

**Backend:** Python, FastAPI, SQLAlchemy, Pydantic

**База данных:** MySQL, Alembic

**OCR и обработка изображений:** Tesseract OCR, pytesseract, OpenCV, Pillow, NumPy

**Frontend:** HTML, CSS, JavaScript

**Тестирование:** pytest, pytest-cov


# Архитектура обработки

Основная обработка выполняется на backend.

```text
Изображение чека
        ↓
Предварительная обработка OpenCV
        ↓
Tesseract OCR
        ↓
Извлечение структурированных данных
        ↓
Категоризация по правилам
        ↓
Опциональная LLM-категоризация
        ↓
MySQL
        ↓
История и статистика
```

OpenCV используется для предварительной обработки изображения перед OCR.

Tesseract преобразует обработанное изображение в текст.

Модуль извлечения анализирует OCR-текст и пытается определить:

- магазин;
- дату;
- итоговую сумму;
- товары;
- количество;
- цену.

После извлечения данных товары классифицируются с помощью набора правил.

Если товар не удалось определить стандартными правилами, он получает категорию `other`. При включённой LLM-категоризации такие позиции могут дополнительно передаваться LLM.


# Архитектурные решения и компромиссы

При разработке рассматривались разные варианты построения OCR pipeline: использование внешнего OCR API, распознавание всего чека непосредственно с помощью LLM или локальная обработка изображения и OCR.

В качестве основного решения был выбран pipeline:

```text
OpenCV → Tesseract OCR → Parser → Rule-based categorization
```

Такой подход позволяет выполнять основную обработку без обязательной зависимости от внешнего OCR или LLM API.

### OpenCV перед OCR

Качество фотографий чеков может значительно отличаться. Поэтому перед распознаванием выполняется предварительная обработка изображения: преобразование в оттенки серого, увеличение небольших изображений, уменьшение шума, повышение локального контраста и адаптивная бинаризация.

Это не устраняет все ошибки OCR, но улучшает входные данные для Tesseract.

### Локальный OCR вместо обязательного внешнего API

Tesseract используется как основной OCR-движок.

Преимущества такого решения:

- приложение может работать без внешнего OCR API;
- отсутствует обязательная стоимость запроса к OCR-сервису;
- изображения не требуется отправлять во внешний OCR-сервис;
- OCR pipeline можно контролировать и тестировать локально.

Компромисс заключается в том, что качество Tesseract сильно зависит от качества исходного изображения и структуры конкретного чека.

### Rule-based категоризация как основной механизм

Основная категоризация товаров выполняется локально по правилам.

Это делает базовую работу приложения независимой от LLM и позволяет получать предсказуемый результат для известных категорий.

### LLM как дополнительный слой

LLM не является обязательной частью основного pipeline.

```text
Распознанный товар
        ↓
Rule-based categorization
        ↓
Не удалось определить
        ↓
other
        ↓
LLM (опционально)
```

По умолчанию:

```env
LLM_ENABLED=false
```

Таким образом, приложение продолжает работать даже без API-ключа и без подключения к LLM.

LLM может использоваться как дополнительный механизм для позиций, которые не удалось классифицировать стандартными правилами.

### Работа с ошибками OCR

На реальных чеках OCR может:

- искажать отдельные символы;
- неправильно распознавать названия товаров;
- объединять или разделять строки;
- пропускать отдельные позиции.

Приложение не должно искусственно создавать отсутствующую информацию, если её невозможно надёжно получить из OCR-текста.

Это означает, что в некоторых случаях сумма распознанных позиций может отличаться от итоговой суммы чека.

# Запуск проекта с нуля на новом компьютере Windows

Эта инструкция рассчитана в том числе на пользователя, который раньше не работал с Git, Python, MySQL или Tesseract. Проект проверен на Windows с Python 3.13. С текущими зафиксированными зависимостями не используйте Python 3.14.

## 1. Создание папки и открытие PowerShell

Откройте Проводник Windows → `Documents` и создайте папку, например:

```text
ReceiptScanner-Test
```

Пример полного пути:

```text
C:\Users\USERNAME\Documents\ReceiptScanner-Test
```

`USERNAME` замените на имя пользователя Windows. Папку `receipt-scanner` внутри вручную создавать не нужно — Git создаст её сам.

Откройте `ReceiptScanner-Test`, нажмите на адресную строку Проводника, введите:

```text
powershell
```

и нажмите `Enter`. PowerShell должен открыться в этой папке:

```text
PS C:\Users\USERNAME\Documents\ReceiptScanner-Test>
```

Все следующие команды вводятся в PowerShell, если явно не указано другое.

## 2. Проверка Git

```powershell
git --version
```

Если Git не найден, установите Git for Windows: `https://git-scm.com/download/win`. После установки закройте PowerShell, снова откройте его из папки `ReceiptScanner-Test` и повторите `git --version`.

## 3. Клонирование проекта

```powershell
git clone https://github.com/donette243/receipt-scanner.git
cd receipt-scanner
```

После `cd` путь должен оканчиваться на:

```text
...\ReceiptScanner-Test\receipt-scanner>
```

Все следующие команды выполняйте из корня `receipt-scanner`.

## 4. Python 3.13 — проверить до создания `.venv`

Проверьте установленные версии:

```powershell
py -0p
```

Проект проверен с Python 3.13.15. Если Python 3.13 уже установлен:

```powershell
py -3.13 --version
```

Если Python 3.13 отсутствует, но команда `py` работает:

```powershell
py install 3.13
py -3.13 --version
```

Если `py` не найден, установите Python 3.13 с `https://www.python.org/downloads/`, затем откройте новый PowerShell и снова проверьте `py -3.13 --version`.

> Важно: на чистом компьютере Python 3.14 с текущим `numpy==2.2.6` приводил к ошибке при загрузке NumPy/OpenCV. Поэтому `.venv` создаётся явно через Python 3.13.

## 5. Создание и активация виртуального окружения

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
```

После активации строка должна начинаться с `(.venv)`, а `python --version` должен показывать Python 3.13.x.

Если PowerShell запрещает запуск `Activate.ps1`:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

`-Scope Process` изменяет политику только для текущего окна PowerShell.

Если `Activate.ps1` не найден, `.venv` не был создан. Сначала выполните `py -3.13 -m venv .venv`.

## 6. Установка Python-зависимостей

Убедитесь, что слева есть `(.venv)`, затем:

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Дождитесь полного завершения установки. `requirements.txt` содержит все Python-зависимости проекта, включая зависимости для API-тестов и опциональной LLM-категоризации.

## 7. MySQL

Приложению нужен MySQL Server. Если MySQL не установлен, используйте официальный MySQL Installer for Windows: `https://dev.mysql.com/downloads/installer/`. При установке оставьте стандартный порт `3306` и сохраните пароль MySQL.

Если MySQL уже установлен, повторная установка не нужна. Даже если `mysql --version` в PowerShell не распознаётся, сервер может быть установлен, но не добавлен в `PATH`. В таком случае используйте MySQL Workbench или MySQL Command Line Client.

Подключитесь к локальному серверу и выполните:

```sql
CREATE DATABASE receiptscanner
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

Проверьте:

```sql
SHOW DATABASES;
```

В списке должна быть `receiptscanner`. Если она уже существует, повторно создавать её не нужно.

## 8. Tesseract OCR и языки

`pytesseract` — Python-обёртка; сам Tesseract OCR устанавливается отдельно. Для Windows можно использовать сборку UB Mannheim: `https://github.com/UB-Mannheim/tesseract/wiki`.

Установите 64-битную версию. Стандартный путь обычно:

```text
C:\Program Files\Tesseract-OCR\tesseract.exe
```

Во время установки обязательно добавьте языковые данные **English, French и Russian**. Проект использует `eng+fra+rus`.

Если команда доступна через PATH:

```powershell
tesseract --version
tesseract --list-langs
```

Если `tesseract` не распознаётся, это не означает, что программа не установлена. Используйте полный путь:

```powershell
& "C:\Program Files\Tesseract-OCR\tesseract.exe" --version
& "C:\Program Files\Tesseract-OCR\tesseract.exe" --list-langs
```

В списке должны быть как минимум:

```text
eng
fra
rus
```

Если видны только `eng` и `osd`, повторно запустите установщик Tesseract, откройте выбор дополнительных языковых данных и добавьте French и Russian, затем снова выполните `--list-langs`.

## 9. Windows N: обязательный Media Feature Pack для OpenCV

Проверьте редакцию Windows:

```powershell
winver
```

Если указано `Windows 10/11 ... N` (например, `Windows 11 Pro N`), OpenCV может завершаться ошибкой:

```text
ImportError: DLL load failed while importing cv2
```

Откройте `Параметры → Приложения → Дополнительные компоненты`, нажмите `Просмотреть компоненты`, найдите `Media Feature Pack`, установите его и **перезагрузите компьютер**.

После перезагрузки снова откройте PowerShell в папке проекта:

```powershell
.\.venv\Scripts\Activate.ps1
python -c "import cv2; print(cv2.__version__)"
```

Для текущей версии проекта ожидается `4.12.0`.

Если Windows не является редакцией N, этот шаг обычно не требуется.

Если DLL-ошибка OpenCV остаётся на обычной Windows, проверьте Microsoft Visual C++ Redistributable x64: `https://aka.ms/vs/17/release/vc_redist.x64.exe`, после установки перезагрузите Windows и повторите тест `import cv2`.

## 10. Создание `.env`

Шаблон `.env.example` уже находится в репозитории. Создайте локальный `.env` автоматически:

```powershell
Copy-Item .env.example .env
notepad .env
```

Пример:

```env
DATABASE_URL=mysql+pymysql://root:YOUR_MYSQL_PASSWORD@localhost:3306/receiptscanner

OCR_LANG=rus+eng+fra
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe

LLM_ENABLED=false
OPENAI_API_KEY=
```

Замените `YOUR_MYSQL_PASSWORD` на свой пароль MySQL. Если используется другой пользователь, замените и `root`. Не отправляйте пароль другим людям и не публикуйте `.env`.

Явный `TESSERACT_CMD` рекомендуется оставить даже тогда, когда Tesseract не добавлен в Windows PATH.

Если пароль MySQL содержит специальные URL-символы (`@`, `:`, `/`, `#`, `%` и т. п.), строка подключения может требовать URL-кодирования.

Сохраните файл (`Ctrl+S`) и закройте Блокнот.

## 11. Миграции базы данных

Убедитесь, что MySQL запущен, база `receiptscanner` существует, `.env` заполнен и `(.venv)` активно. Затем:


Alembic создаст необходимые таблицы. `Access denied` обычно означает неверные данные MySQL в `DATABASE_URL`; `Unknown database 'receiptscanner'` — база ещё не создана.

# Использование

После запуска приложения:

1. Откройте главную страницу.
2. Выберите изображение кассового чека.
3. Запустите распознавание.
4. Дождитесь завершения OCR.
5. Проверьте распознанные данные.
6. Откройте историю чеков.
7. Проверьте статистику расходов.

После обработки приложение может определить:

- магазин;
- дату;
- итоговую сумму;
- товары;
- количество;
- цену;
- категорию расходов;
- исходный OCR-текст.

Результат сохраняется в MySQL и становится доступен в истории и статистике.

# Категории расходов

Приложение использует следующие категории:

- продукты питания;
- напитки;
- гигиена;
- одежда;
- электроника;
- транспорт;
- лекарства;

- другое.

Если товар невозможно надёжно классифицировать, используется техническая категория:

```text
other
```

# Ограничения OCR

Качество распознавания зависит от:

- разрешения изображения;
- освещения;
- качества печати;
- состояния чека;
- языка;
- расположения текста;
- качества фотографии.

На повреждённых, размытых или плохо напечатанных чеках Tesseract может допускать ошибки в названиях товаров или пропускать отдельные позиции.

Основная цель приложения — извлекать информацию, которую можно получить из OCR-текста, не подменяя отсутствующие данные искусственно созданными значениями.


# Безопасность

Файл `.env` исключён из Git через `.gitignore`.

Также из репозитория исключаются:

- виртуальные окружения;
- кэш Python;
- кэш pytest;
- локальные базы данных;
- загруженные изображения чеков;
- временные обработанные изображения;
- логи.

Не публикуйте:

- пароли MySQL;
- API-ключи;
- персональные чеки;
- другие секретные данные.
