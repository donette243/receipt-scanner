# Receipt Scanner / Categorizer

Веб-приложение для распознавания кассовых чеков, автоматического извлечения информации о покупках, категоризации товаров и анализа расходов.

Пользователь загружает фотографию чека, после чего приложение обрабатывает изображение с помощью OpenCV, распознаёт текст через Tesseract OCR, извлекает данные о покупке, определяет категории товаров и сохраняет результат в MySQL.

## Основные возможности

- загрузка изображений кассовых чеков;
- предварительная обработка изображений с помощью OpenCV;
- распознавание текста через Tesseract OCR;
- поддержка русского, английского и французского языков;
- извлечение магазина, даты и итоговой суммы;
- извлечение названий товаров, количества и цены;
- автоматическая категоризация товаров;
- опциональная категоризация через LLM;
- сохранение результатов в MySQL;
- просмотр истории чеков;
- удаление сохранённых чеков;
- статистика расходов по категориям;
- REST API на FastAPI;
- интерактивная документация Swagger UI;
- миграции базы данных через Alembic;
- автоматические тесты с pytest;
- адаптивный веб-интерфейс на русском языке.

## Стек технологий

**Backend:** Python, FastAPI, SQLAlchemy, Pydantic

**База данных:** MySQL, Alembic

**OCR и обработка изображений:** Tesseract OCR, pytesseract, OpenCV, Pillow, NumPy

**Frontend:** HTML, CSS, JavaScript

**Тестирование:** pytest, pytest-cov


# Архитектура обработки

Основная обработка выполняется на backend.

```text
Изображение чека
        ↓
Предварительная обработка OpenCV
        ↓
Tesseract OCR
        ↓
Извлечение структурированных данных
        ↓
Категоризация по правилам
        ↓
Опциональная LLM-категоризация
        ↓
MySQL
        ↓
История и статистика
```

OpenCV используется для предварительной обработки изображения перед OCR.

Tesseract преобразует обработанное изображение в текст.

Модуль извлечения анализирует OCR-текст и пытается определить:

- магазин;
- дату;
- итоговую сумму;
- товары;
- количество;
- цену.

После извлечения данных товары классифицируются с помощью набора правил.

Если товар не удалось определить стандартными правилами, он получает категорию `other`. При включённой LLM-категоризации такие позиции могут дополнительно передаваться LLM.


# Архитектурные решения и компромиссы

При разработке рассматривались разные варианты построения OCR pipeline: использование внешнего OCR API, распознавание всего чека непосредственно с помощью LLM или локальная обработка изображения и OCR.

В качестве основного решения был выбран pipeline:

```text
OpenCV → Tesseract OCR → Parser → Rule-based categorization
```

Такой подход позволяет выполнять основную обработку без обязательной зависимости от внешнего OCR или LLM API.

### OpenCV перед OCR

Качество фотографий чеков может значительно отличаться. Поэтому перед распознаванием выполняется предварительная обработка изображения: преобразование в оттенки серого, увеличение небольших изображений, уменьшение шума, повышение локального контраста и адаптивная бинаризация.

Это не устраняет все ошибки OCR, но улучшает входные данные для Tesseract.

### Локальный OCR вместо обязательного внешнего API

Tesseract используется как основной OCR-движок.

Преимущества такого решения:

- приложение может работать без внешнего OCR API;
- отсутствует обязательная стоимость запроса к OCR-сервису;
- изображения не требуется отправлять во внешний OCR-сервис;
- OCR pipeline можно контролировать и тестировать локально.

Компромисс заключается в том, что качество Tesseract сильно зависит от качества исходного изображения и структуры конкретного чека.

### Rule-based категоризация как основной механизм

Основная категоризация товаров выполняется локально по правилам.

Это делает базовую работу приложения независимой от LLM и позволяет получать предсказуемый результат для известных категорий.

### LLM как дополнительный слой

LLM не является обязательной частью основного pipeline.

```text
Распознанный товар
        ↓
Rule-based categorization
        ↓
Не удалось определить
        ↓
other
        ↓
LLM (опционально)
```

По умолчанию:

```env
LLM_ENABLED=false
```

Таким образом, приложение продолжает работать даже без API-ключа и без подключения к LLM.

LLM может использоваться как дополнительный механизм для позиций, которые не удалось классифицировать стандартными правилами.

### Работа с ошибками OCR

На реальных чеках OCR может:

- искажать отдельные символы;
- неправильно распознавать названия товаров;
- объединять или разделять строки;
- пропускать отдельные позиции.

Приложение не должно искусственно создавать отсутствующую информацию, если её невозможно надёжно получить из OCR-текста.

Это означает, что в некоторых случаях сумма распознанных позиций может отличаться от итоговой суммы чека.

# Запуск проекта с нуля

## 1. Клонирование репозитория

```powershell
git clone https://github.com/donette243/receipt-scanner.git
cd receipt-scanner
```

## 2. Создание виртуального окружения

Для Windows:

```powershell
python -m venv .venv
```

Активация:

```powershell
.venv\Scripts\Activate.ps1
```

После активации в начале строки PowerShell должно появиться:

```text
(.venv)
```

## 3. Установка зависимостей

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Настройка MySQL

Для работы приложения необходим MySQL.

Создайте базу данных:

```sql
CREATE DATABASE receiptscanner
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

Проверить наличие базы можно командой:

```sql
SHOW DATABASES;
```

В списке должна присутствовать база:

```text
receiptscanner
```

## 5. Установка Tesseract OCR

Приложение использует Tesseract OCR для распознавания текста на изображениях чеков.

Необходимо установить языковые данные:

```text
rus
eng
fra
```

Проверить установленную версию:

```powershell
tesseract --version
```

Проверить доступные языки:

```powershell
tesseract --list-langs
```

В списке должны присутствовать:

```text
eng
fra
rus
```

Если команда `tesseract` недоступна через PATH, путь к исполняемому файлу можно указать через `TESSERACT_CMD` в `.env`.

Пример:

```env
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

## 6. Настройка переменных окружения

В репозитории находится файл:

```text
.env.example
```

Создайте локальный `.env`:

```powershell
Copy-Item .env.example .env
```

Укажите в `.env` параметры своей базы данных:

```env
DATABASE_URL=mysql+pymysql://username:password@localhost:3306/receiptscanner

OCR_LANG=rus+eng+fra
TESSERACT_CMD=

LLM_ENABLED=false
OPENAI_API_KEY=
```

Замените `username` и `password` на данные своего пользователя MySQL.

Файл `.env` содержит локальные настройки и возможные секретные данные, поэтому он исключён из Git.

## 7. Применение миграций

После создания базы данных и настройки `.env` выполните:

```powershell
alembic upgrade head
```

Alembic создаст необходимые таблицы в базе данных.

## 8. Запуск приложения

```powershell
uvicorn app.main:app --reload
```

После успешного запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:8000
```

## 9. Проверка backend

Health endpoint:

```text
http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Документация REST API:

```text
http://127.0.0.1:8000/docs
```

# Использование

После запуска приложения:

1. Откройте главную страницу.
2. Выберите изображение кассового чека.
3. Запустите распознавание.
4. Дождитесь завершения OCR.
5. Проверьте распознанные данные.
6. Откройте историю чеков.
7. Проверьте статистику расходов.

После обработки приложение может определить:

- магазин;
- дату;
- итоговую сумму;
- товары;
- количество;
- цену;
- категорию расходов;
- исходный OCR-текст.

Результат сохраняется в MySQL и становится доступен в истории и статистике.

# Категории расходов

Приложение использует следующие категории:

- продукты питания;
- напитки;
- гигиена;
- одежда;
- электроника;
- транспорт;
- лекарства;

Если товар невозможно надёжно классифицировать, используется техническая категория:

```text
other
```

# Ограничения OCR

Качество распознавания зависит от:

- разрешения изображения;
- освещения;
- качества печати;
- состояния чека;
- языка;
- расположения текста;
- качества фотографии.

На повреждённых, размытых или плохо напечатанных чеках Tesseract может допускать ошибки в названиях товаров или пропускать отдельные позиции.

Основная цель приложения — извлекать информацию, которую можно получить из OCR-текста, не подменяя отсутствующие данные искусственно созданными значениями.


# Безопасность

- виртуальные окружения;
- кэш Python;
- кэш pytest;
- локальные базы данных;
- загруженные изображения чеков;
- временные обработанные изображения;
- логи.

Не публикуйте:

- пароли MySQL;
- API-ключи;
- персональные чеки;
- другие секретные данные.
