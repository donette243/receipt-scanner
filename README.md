# Receipt Scanner / Categorizer

Веб-приложение для распознавания кассовых чеков, автоматического извлечения информации о покупках и анализа расходов.

Пользователь загружает фотографию чека, после чего приложение обрабатывает изображение с помощью OpenCV, распознаёт текст через Tesseract OCR, извлекает товары и суммы, определяет категории расходов и сохраняет результат в MySQL.

## Основные возможности

- загрузка изображения кассового чека;
- предварительная обработка изображения с OpenCV;
- распознавание текста с помощью Tesseract OCR;
- поддержка русского, английского и французского языков;
- извлечение магазина, даты и общей суммы чека;
- извлечение названий товаров, количества и цены;
- автоматическая категоризация расходов;
- дополнительная категоризация через LLM;
- сохранение чеков в MySQL;
- просмотр истории чеков;
- удаление сохранённых чеков;
- статистика расходов по категориям;
- REST API на FastAPI;
- интерактивная документация Swagger;
- миграции базы данных через Alembic;
- автоматические тесты pytest;
- адаптивный веб-интерфейс на русском языке.

## Стек технологий

**Backend:** Python, FastAPI, SQLAlchemy, Pydantic

**База данных:** MySQL, Alembic

**OCR и обработка изображений:** Tesseract OCR, pytesseract, OpenCV, Pillow, NumPy

**Frontend:** HTML, CSS, JavaScript

**Тестирование:** pytest, pytest-cov

# Запуск проекта с нуля

Ниже приведена полная инструкция для пользователя, который впервые клонирует проект с GitHub и не имеет его локальной копии.

## 1. Клонирование репозитория

```powershell
git clone <URL-РЕПОЗИТОРИЯ>
cd receiptScanner
```

> После публикации проекта на GitHub вместо `<URL-РЕПОЗИТОРИЯ>` необходимо использовать фактический URL репозитория.

## 2. Создание виртуального окружения

Для Windows:

```powershell
python -m venv .venv
```

Активация:

```powershell
.venv\Scripts\Activate.ps1
```

После активации в начале строки PowerShell должно появиться:

```text
(.venv)
```

## 3. Установка зависимостей Python

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Установка MySQL

Для работы приложения необходим MySQL 8.

После установки MySQL необходимо создать базу данных:

```sql
CREATE DATABASE receiptscanner
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

Проверить наличие базы можно командой:

```sql
SHOW DATABASES;
```

В списке должна присутствовать:

```text
receiptscanner
```

## 5. Установка Tesseract OCR

Приложение использует Tesseract OCR для распознавания текста на изображениях чеков.

Необходимо установить Tesseract и языковые данные:

```text
rus
eng
fra
```

Проверить установку Tesseract можно командой:

```powershell
tesseract --version
```

Проверить установленные языки:

```powershell
tesseract --list-langs
```

В списке должны присутствовать:

```text
eng
fra
rus
```

Если команда `tesseract` недоступна через PATH, путь к исполняемому файлу можно указать в переменной `TESSERACT_CMD` в `.env`.

Например:

```env
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

## 6. Настройка переменных окружения

В репозитории находится файл:

```text
.env.example
```

Создайте из него локальный `.env`:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите данные своей MySQL:

```env
DATABASE_URL=mysql+pymysql://username:password@localhost:3306/receiptscanner

OCR_LANG=rus+eng+fra
TESSERACT_CMD=

LLM_ENABLED=false
OPENAI_API_KEY=
```

Замените:

```text
username
password
```

на имя пользователя и пароль вашей локальной MySQL.

Файл `.env` содержит локальные настройки и секретные данные и не должен отправляться в GitHub.

## 7. Создание таблиц базы данных

После настройки MySQL примените миграции Alembic:

```powershell
alembic upgrade head
```

Alembic создаст необходимые таблицы в базе `receiptscanner`.

## 8. Запуск приложения

Запустите FastAPI:

```powershell
uvicorn app.main:app --reload
```

При успешном запуске появится сообщение примерно такого вида:

```text
Uvicorn running on http://127.0.0.1:8000
Application startup complete.
```

## 9. Открытие веб-интерфейса

Откройте в браузере:

```text
http://127.0.0.1:8000
```

После этого должна открыться главная страница Receipt Scanner с интерфейсом загрузки чека.

## 10. Проверка backend

Проверка состояния приложения:

```text
http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Документация REST API:

```text
http://127.0.0.1:8000/docs
```

FastAPI автоматически откроет Swagger UI со всеми доступными endpoint приложения.

# Как работает обработка чека

```text
Изображение чека
        ↓
Предварительная обработка OpenCV
        ↓
Tesseract OCR
        ↓
Извлечение данных
        ↓
Категоризация товаров
        ↓
Опциональная LLM-категоризация
        ↓
Сохранение в MySQL
        ↓
История и статистика
```

OpenCV предварительно обрабатывает изображение для улучшения качества распознавания.

Tesseract OCR преобразует изображение в текст.

Модуль извлечения анализирует полученный текст и пытается определить магазин, дату, итоговую сумму и позиции чека.

После этого товары распределяются по категориям расходов.

---

# Категории расходов

В приложении предусмотрены следующие категории:

- продукты питания;
- напитки;
- гигиена;
- одежда;
- электроника;
- транспорт;
- лекарства;
- ресторан;
- другое.

Если товар невозможно надёжно определить, используется категория `other`.

# Опциональная LLM-категоризация

По умолчанию использование LLM отключено:

```env
LLM_ENABLED=false
```

Основная категоризация работает без LLM.

При наличии соответствующей конфигурации LLM может использоваться дополнительно для товаров, которые не удалось классифицировать стандартными правилами.

Секретные API-ключи должны храниться только в `.env` и никогда не должны публиковаться в GitHub.

# Ограничения OCR

Качество распознавания зависит от:

- разрешения изображения;
- освещения;
- качества печати чека;
- состояния бумаги;
- языка;
- расположения текста;
- качества фотографии.

На повреждённых, размытых или плохо напечатанных чеках Tesseract может допускать ошибки в названиях товаров или пропускать отдельные позиции.

Приложение не должно искусственно придумывать отсутствующую информацию, если OCR не смог надёжно её распознать.

# Безопасность

Файл `.env` исключён из Git через `.gitignore`.

Также из репозитория исключаются:

- локальные виртуальные окружения;
- кэш Python;
- pytest cache;
- локальные базы данных;
- загруженные изображения чеков;
- временные изображения;
- логи.

Не публикуйте в репозитории реальные:

- пароли MySQL;
- API-ключи;
- персональные чеки;
- другие секретные данные.
